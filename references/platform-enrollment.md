# 平台活动报名：操作方法与已踩坑

本文记录平台活动报名页（`/act/goods_price/confirm`）的实际操作方式。示例中的活动 ID、商品 ID、店铺均为占位符，不要写死真实值。

## 1. 页面与字段

报名页参数：

- `activityId`：活动 ID
- `activityType`：活动类型；来源是活动卡片「去报名」链接的 `activityType` 参数。`activity-list` 不返回该字段，需从卡片 URL 读取，不要用 activityId 猜。
- 常见入口由活动卡片点击打开；不要直接猜 `/act/enroll`。

页面主要区域：

- 活动名称 / 报名资格 / 报名时间
- 运费模板要求
- 商品搜索
- 批量设置活动价
- 商品表：商品信息、规格、建议价、活动价、运费模板、操作
- 底部：流量保护、报名须知、已选商品数、确认提交

## 2. 商品表是虚拟滚动

这是最大的坑。

- 页面显示的“已选商品 N 个”不等于当前表格渲染行数。
- 表格只渲染当前窗口附近的行。
- 必须持续滚动，边滚边采集商品 ID。
- 滚到底部出现「点击加载更多商品」时点击，然后继续滚动。
- 判断“读全”不能只看当前可见的 3/6/10 行。
- 实测一个活动在虚拟滚动下可采集到约 50 个商品 ID；具体数量以页面为准。
- 商品级摘要扫描可先只读标题、当前价、活动价、折扣，不要求第一遍展开全部 SKU。

推荐采集循环：

1. `scrollBy(0, 350~400)`
2. 等待渲染
3. 收集当前所有 `tr` 中的商品 ID
4. 到达底部时点击「点击加载更多商品」
5. 没有新增且没有加载更多后停止
6. 用已收集的 ID 列表做完整性校验

## 3. 清空默认已选

默认可能带出大量已选商品（例如 50 个）。

- 表头左侧蓝色复选框是**全选/取消全选**。
- 它是自定义 checkbox，隐藏 input 的 `.click()` 不一定生效。
- 要点它的 `label`，最好用鼠标点击。
- 点击后核对底部是否为「已选商品 0 个」。
- 清空选择不等于清空表格；表格商品仍会保留。

## 4. 搜索商品

页面搜索框 placeholder：

> 输入商品名称或ID搜索商品，多个ID以逗号隔开

操作：

1. 鼠标点击输入框
2. 键盘输入商品 ID
3. 按 Enter

会打开「搜索活动商品」结果层，通常包含：

- 可报名商品 / 不可报名商品
- 商品信息、拼单价、库存

注意：

- 用原生 setter + 手动 `input` 事件不一定会触发搜索。
- 用真实键盘输入 + Enter 更可靠。
- 搜索层用于查资格/找商品，不自动等于主表筛选。
- 搜索层不要点「确认」除非用户明确要加入。

## 5. 只勾选授权商品

- 商品行左侧复选框同样是自定义控件。
- 点 `input.click()` 可能无效，点行内 `label` 的鼠标坐标才有效。
- 勾选后核对底部「已选商品 1 个」。
- 不要因为商品在表格里就顺手勾选。
- 用户没说“报名”，只查看，不勾选。

## 6. 展开全部 SKU

坑：点「展开更多规格」文字本身经常没反应。

正确方式：

- 找到目标商品所在 `tr` 分组。
- 该分组通常为 `rowspan`，后接 SKU 行和「展开更多规格」行。
- 在「展开更多规格」行里点击**最右侧的小箭头/下拉图标**（通常是该行最后一个 `span`/`svg`）。
- 不要只点文字。
- 成功后页面出现「收起」，SKU 行数增加。
- 展开后目标商品 ID 通常还在，可用它继续锁定分组。
- 解析目标分组时，从目标商品行开始，遇到下一个 `ID:` 行停止，避免串到下一个商品。

## 7. 价格与折扣解析

每个 SKU 行可能包含：

- 规格名
- 当前价
- 线上库存
- 活动价
- 折扣

注意：

- 不是所有 SKU 都有「约 N 折」。
- 有些商品活动价会**高于**当前价，页面不显示折扣。
- 解析时要允许折扣为空。
- 不能把空折扣当成解析失败。
- 同一商品不同 SKU 折扣可以差很多；同一活动不同商品也可以差很多。
- 实测有商品全部 9 折，也有商品出现 1.4 折、2 折、2.6 折等。
- 必须逐 SKU 读，不要合成一个平均折扣。

## 8. 提交前的确认门

提交是写操作，必须显式确认。

流程：

1. 用户指定商品
2. 用户明确说「报名/报名这个」
3. 勾选商品
4. 问：还有其他商品要一起报名吗？
5. 用户确认没有其他商品
6. 问流量保护
7. 用户回答后，才允许点「确认提交」

流量保护默认值：

- 默认勾选「开启流量保护」
- 当前价失效时降价 3%
- 最高降价金额 5 元

选项：

- 保持默认开启
- 关闭
- 修改降价比例

不要自动替用户决定。

## 9. 提交与回读

点「确认提交」后：

- 成功提示通常为「N 个商品报名成功」
- 选择数会归零
- 弹窗按钮：继续报名 / 查看报名记录

回读：

- 打开「查看报名记录」
- 记录页 URL 形如 `/act/register_record`
- 按商品 ID 搜索记录
- 核对：活动 ID、商品 ID、提交时间、活动价、外场活动价、状态

常见状态：

- 报名成功
- 报名进行中
- 价格暂时失效
- 活动下线
- 审核中

即使提示报名成功，也要检查是否有「价格暂时失效」「查看屏蔽中规格」等提示。

## 10. 逐步点击操作表

> 不要写死屏幕坐标；每次都用元素当前 `getBoundingClientRect()` 取中心点再鼠标点击。

| 步骤 | 目标元素 | 具体动作 | 成功校验 |
|---|---|---|---|
| 1 | 活动报名页 | 打开 `/act/goods_price/confirm?activityId=...&activityType=...` | 页面出现商品表、已选商品数 |
| 2 | 表头蓝色全选框 | 找 `th` 里的 `label`，鼠标点中心 | 底部变为「已选商品 0 个」 |
| 3 | 商品表 | `window.scrollBy(0, 350~400)`，每步收集 `tr` 里的 `ID:` | 商品 ID 数量持续增加 |
| 4 | 「点击加载更多商品」 | 滚到底后找纯文本按钮，点击 | 表格追加商品；继续滚动 |
| 5 | 商品搜索框 | 点输入框，键盘输入商品 ID，按 Enter | 出现「搜索活动商品」结果层 |
| 6 | 目标商品行 | 找 `tr` 文本含 `ID: <goodsId>`；点该行第一个 `label` | 底部变为「已选商品 1 个」 |
| 7 | 「展开更多规格」行 | 在目标商品同一 `table` 后续 `tr` 中找含「展开更多规格」的行；点该行最后一个 `span`/`svg` | 出现「收起」，SKU 行增加 |
| 8 | 目标商品分组 | 从目标 `tr` 开始读，遇到下一个 `ID:` 行停止 | 得到该商品全部 SKU 行 |
| 9 | 流量保护 | 找底部 label 文本含「开启流量保护」，鼠标点 label | `input.checked` 变为 false/true |
| 10 | 确认提交 | 找纯文本按钮「确认提交」，点击 | 出现「N 个商品报名成功」 |
| 11 | 查看报名记录 | 点「查看报名记录」 | 跳到 `/act/register_record` |
| 12 | 报名记录 | 找商品 ID 对应行 | 核对活动 ID、活动价、状态 |

### 点击失败时的处理

| 现象 | 原因 | 处理 |
|---|---|---|
| 点隐藏 input 没反应 | 自定义 checkbox | 点它外层 `label`，用鼠标 |
| 表头全选没反应 | 元素不在可视区/被 sticky 遮挡 | `scrollIntoView` 后再点 label |
| 点「展开更多规格」文字没反应 | 文字不是点击热区 | 点该行最后一个 `span`/`svg` 小箭头 |
| 只看到 3/6 个商品 | 虚拟滚动只渲染窗口 | 继续滚动并点「点击加载更多商品」 |
| 展开后读到别的商品 | 分组边界没切 | 遇到下一个 `ID:` 行立即停止 |
| 折扣为空 | 活动价不低于当前价 | 保留空折扣，并标记价格异常 |
| 扫描超过 300 秒 | 每个商品都回顶部重扫 | 第一遍只读商品摘要；指定商品后再读全 SKU |

## 11. 多商品报名

一次报名多个商品时：

1. 清空表头全选
2. 对每个 `goodsIds` 逐个滚动定位、点商品行 label
3. 校验「已选商品 N 个」必须等于 `goodsIds.length`
4. 设置流量保护
5. 用户确认后点「确认提交」
6. 成功提示应为「N 个商品报名成功」
7. 逐个商品回读报名记录

注意：

- 多商品不要只校验第一个商品，必须校验已选数量。
- 提交后已选数会归零。
- 记录页同一商品可能有多条历史活动记录，必须按活动 ID 区分。
- 报名成功不等于价格已生效，仍需检查「暂时失效」「审核中」。

## 12. 报名状态核对

“商品是否可报名”优先以**当前活动页搜索结果**为准，不要只看历史报名记录。

搜索规则：

- 出现「商品已生效当前活动，无需重复报名」→ 已生效
- 搜索到商品 ID，但没有已生效提示 → 可报名
- 完全搜不到 → 未找到 / 不可报名

注意：搜索页固定有「可报名商品 / 不可报名商品」两个标签，不能因为页面出现「不可报名商品」字样就判定当前商品不可报名。

## 13. 价格暂时失效

报名记录里可能显示：

> 活动价: N（暂时失效） 查看屏蔽中规格

点「查看屏蔽中规格」会打开「价格失效原因」弹窗。

已见原因：

> 商品系统审核中，预计需要 2～3 天。请保持活动报名状态，切勿退出，以免延长审核周期。

处理：

- 不要因为“暂时失效”就取消报名
- 不要重复提交
- 记录具体原因
- 提示用户保持报名状态，等待审核

## 14. 进入活动页的阻塞弹窗

进入营销活动/报名页时，可能先弹出一个提示框：

> 您有 N 个商品因不符合活动要求，即将影响活动权益，请尽快修改！

弹窗内容：

- 商品列表
- 商品 ID
- 资源位活动
- 提醒原因，例如：
  - 此商品缺乏优势，已失去活动流量
  - 请尽快确认修改

处理原则：

1. 先读取弹窗内商品/原因并记录
2. 不要点「立即改价」：这是改价写操作
3. 点「稍后处理」或右上角 X 关闭
4. 关闭后再继续活动读取/报名

还可能同时出现：

> 设置营销联系电话并开启「改价电话提醒」

处理：

- 不要自动点「立即设置」
- 用 X / 点击空白 / Escape 关闭
- 不修改店铺联系电话

## 15. 活动列表：可见 75 条 vs 隐藏 103 条

活动首页有两套列表：

- 主页面可见列表：75 条 / 4 页
- 右侧隐藏抽屉「全部活动」：103 条 / 6 页

读取可见列表时：

- 活动名称从 `[class*=activity-item_newActivityName]` 读取，不要从整行文本猜
- 75 条名称必须非空；展示给用户用活动名称，ID 仅作技术定位

- 卡片 selector 用 `[class*=activity-item_newContainer]`（前缀匹配，不要精确 class）
- 必须排除祖先含 `activity-list-drawer` 的卡片
- 分页按钮是 `LI[class*=PGT_pagerItem]`，不是无子元素 span
- 点击页码前滚到页面底部，按屏幕可见坐标点击
- 不要把隐藏抽屉的 103 条和主列表 75 条混在一起

## 16. 活动入口探查协议（不要写死流程）

不同活动点击后不一定立刻跳转，可能只是：

- 当前页右侧弹出活动详情抽屉
- 弹出活动详情弹窗
- 切换到「机遇商品报名」tab
- 打开新标签页
- 打开选品页
- 打开确认页
- 只弹出风险提示

所以不能假设「点了去报名就一定进入某个 URL」。

### 每次点击后的固定探查步骤

1. 记录点击前的活动名称、activityId、入口类型
2. 点击入口
3. 等待 2～3 秒
4. 检查：
   - URL 是否变化
   - 是否出现新标签页/新页面
   - 当前页是否出现抽屉/弹窗
   - 页面标题/面包屑
   - 可见按钮文本
   - 已选商品数
   - 风险提示
5. 再决定下一步

### 必查风险信息

- 不符合活动要求
- 报名资质：不符合 / 符合
- 活动价暂时失效
- 查看屏蔽中规格
- 运费模板不满足要求
- 库存为 0
- 活动下线
- 商品缺乏优势
- 流量保护状态

### 状态分类

| 状态 | 典型特征 | 下一步 |
|---|---|---|
| 无变化 | URL/页面/抽屉都没变 | 不要重复盲点；检查卡片标题、详情按钮、入口是否点错 |
| 详情抽屉 | 右侧出现活动规则、立即报名 | 先读规则，再决定是否点立即报名 |
| 机遇商品报名 | `tab=1`、待报名商品 | 商品卡片选择 + 确认报名，不等于活动详情 |
| 选品页 | `choose_goods`、三步进度 | 选商品 → 确认选择 |
| 确认页 | `goods_price/confirm`、活动价/券面额 | 核价、看风险、再决定是否提交 |
| 风险弹窗 | 不符合活动要求/立即改价 | 只记录并关闭，不点立即改价 |
| 成功页 | 报名成功/报名记录 | 回读记录、检查失效原因 |

### 操作原则

- 不根据按钮文字猜流程
- 不默认点击后会跳转
- 每次点击后先探查，再分支
- 不点「立即改价」「全店报名」「确认提交」除非用户明确授权
- 入口点错时不要连续重复点击
- 页面没有变化时，优先检查是否打开了抽屉，而不是继续点按钮

## 17. 各类型定位与 SKU 展开方法

| 类型 | 产品定位 | 勾选方式 | 展开 SKU | 额外字段/风险 |
|---|---|---|---|---|
| 普通确认页（22385/21595/21365/24314） | `tr` 里按 `ID:` 定位 | 商品行 checkbox 的 label | 目标商品同表后续行，点「展开更多规格」行最后一个 span/svg | 21365 多活动库存；24314 初始加载/默认已选 |
| 场景专属券选品页（22196） | 商品卡片按 `ID <id>` 定位 | 点卡片自动勾选；底部确认选择 | 选品页不展开 SKU；进入 confirm 后同普通确认页 | activityType=420，多优惠券面额 |
| 混合出资券（21408） | 当前页无商品表 | 先同意协议 | 无，同意前无 SKU | 协议弹窗，高风险，未授权不点 |
| 同价报名（24314） | confirm 表，等待加载 | 默认可能已选 50 | 同普通确认页 | 「无需降价」但表内仍可能出现活动价 |

### 已验证

- 21365：`ID: 988004082382` 定位成功，展开后出现「收起」，读取 16 行价格
- 24314：等待后从「加载中」变为 6 个商品 ID、默认已选 50 个，表格结构同普通确认页
- 22196：商品卡片点击自动勾选 1 个，确认选择后进入 confirm 页，展开方式同普通确认页

### 注意

- 选品页的“卡片点击”和确认页的“表格 checkbox”不是同一套操作
- 同价报名开始可能暂无数据，需要等待/刷新后再定位
- 21408 未同意协议前没有商品表，不能提前按普通活动处理


### 定位必须滚动重试

确认页商品很多时，目标行可能不在当前渲染窗口。不能第一次查不到就判定“没有这个商品”。

正确做法：

- 每 300～500px 滚动一次
- 每步重新按商品名称/ID 找行
- 找到后 `scrollIntoView`
- 再点展开箭头
- 展开后校验「收起」

实测：限量活动、满减活动、同价报名中，两个商品均通过滚动重试定位并展开成功。

### 场景专属券不能直接打开确认页

场景专属券的确认页依赖“选择商品”页带来的已选状态。

直接访问 `goods_price/confirm?activityId=...&from=chooseGoods` 会丢失已选商品，目标商品可能不存在。

必须：

1. 从活动详情点「立即报名」
2. 进入 `choose_goods`
3. 点商品卡片勾选
4. 点「确认选择」
5. 再进入确认页

## 18. 确认页搜索弹窗：只查资格，不用来选品

确认页输入商品名称/ID 会弹出「搜索活动商品」模态框。

用途只有一个：

- 查该商品在当前活动能不能报名
- 查询后点「取消」关闭

不要用弹窗「确认」来勾选商品。弹窗会遮挡主表，背后商品行点击无效。

选品正确方式：

1. 关闭搜索弹窗
2. 回到主表
3. 滚动重试定位目标商品行
4. 点商品行 checkbox 的 label
5. 校验已选数量

实测：

- 弹窗打开时，点主表商品行始终不生效
- 关闭弹窗后，主表定位 4 个商品并逐个勾选，数量从 0 正确变成 4
- 能直接定位时，搜索这一步可以省略

## 19. 本轮已验证与未解决

已验证：

- 搜索弹窗会遮挡主表，必须关闭后再点商品行
- 关闭弹窗后，主表可以正确选中 4 个授权商品
- 已选数量能从 0 准确到 4

## 20. 已知限制

- 第一遍只做商品级摘要，不展开全部 SKU；指定商品后再读全 SKU。
- 50 个商品逐个“回顶部定位 + 展开”会非常慢，曾超过 300 秒甚至卡死；不要用这种方式。
- 虚拟表格在展开/滚动后可能重渲染，已采集的 ID 要单独保存，不能依赖当前 DOM 行数。
- 平台活动列表本身还有分页问题，`activity-list` 尚未保证 102 条全量。
- 本文件只覆盖平台活动报名；优惠券、店铺活动创建另有流程。


## 报名前必须确认流量保护

- 不得默认替用户开启/关闭。
- preview 后单独问：流量保护 `on` 还是 `off`、最高降价金额是否接受。
- `confirmSubmit:true` 时必须显式提供 `trafficProtection: "on" | "off"`，否则 run.mjs 返回 `traffic_protection_required`，不打开报名页。

## 记录页未找到时

`platform-record` 的 `found=false` 只代表当前记录页签/当前页没找到，不等于未报名。必须用 `platform-status` 查活动页状态：`已生效当前活动` / `可报名` / `未找到`。
