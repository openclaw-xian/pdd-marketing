# 优惠券创建：操作步骤与踩坑

范围只做 3 种：

- 商品立减券
- 店铺关注券
- 惊喜券

入口：

- 概览：`/tool/coupon`
- 管理：`/tool/coupon?tab=1`
- 商品立减创建：`/tool/coupon/create?chooseType=7`
- 店铺关注创建：`/tool/coupon/create?chooseType=3`
- 惊喜券创建：`/tool/surprise-coupon`

## 1. 类型选择

创建页点「修改优惠券类型」会弹出「选择优惠券类型」。

- 共 10 个选项
- 只选 3 种
- 其余直接关闭，不进入创建

## 2. 商品立减券

字段：

- 优惠券名称：默认“商品立减券”，maxLength 20
- 领取时间：默认 365 天
- 使用时间：领取后 2 小时内
- 活动商品：选择商品
- 额外优惠：金额，可勾选
- 报名全站营销：勾选项，会附带额外设置
- 同步设置惊喜券额外优惠：金额，可勾选
- 创建

实测限制：

- 目标商品面额区间曾显示 1～12 元
- 发行张数上限 1,000,000
- 奖励区间以页面提示为准

重要：

- 额外优惠/全站营销/惊喜券额外优惠不会自动取消
- 创建前必须逐个确认 checkbox
- 曾因未取消“全站营销”，创建成功后附带“全站营销额外设置1元”
- 该券只能结束，不能直接改额外优惠

## 3. 店铺关注券

字段：

- 使用范围：全店商品（店铺券）/ 指定商品（商品券）
- 优惠券名称：默认“指定商品店铺关注券”，maxLength 20
- 领取时间：默认 365 天
- 使用时间：领取后 N 天内可用
- 活动商品：仅“指定商品”需要
- 创建

实测限制：

- 目标商品面额区间 6～12 元
- 5 元不可用
- 发行张数上限 1,000,000

## 4. 惊喜券

字段：

- 优惠券名称：默认“惊喜券”，maxLength 20
- 领取时间：默认 90 天
- 每人限领：1张/2张/3张
- 活动商品：选择商品
- 创建

实测限制：

- 目标商品面额建议区间 9～13 元
- 低于 9 或高于 13 时券后价变 `--`，提示“建议优惠区间参考：9～13”
- 5 元不可用
- 发行张数上限 1,000,000
- 日期被清空或非法时提示“不能为空”
- 直接改日期输入框会被清空，必须用日期选择器

## 5. 选择商品弹窗

- 共 53 个商品
- 每页 20 个，共 3 页
- 没有按商品 ID 搜索的输入框
- 目标商品可能在第 2/3 页

正确选择：

1. 打开选择商品
2. 翻到对应页
3. 按商品 ID/名称定位行
4. 点该商品行 checkbox
5. 确认只选中目标行
6. 点「确认选择」
7. 创建页显示“已选 N 个商品”
8. 核对 N

踩坑：

- 点错表头/整行区域会一次选中整页 20 个商品
- 选择器没有 ID 搜索，不能只查第 1 页
- 选错商品可在创建页点该行「删除」
- 切换券类型可能保留/重置已选商品，必须重新核对

## 6. 已选商品删除

- 创建页每行有「删除」
- 点对应行删除
- 只删该商品
- 删除后核对已选数量

## 7. 创建成功

成功提示：

- “1个商品提交成功”
- “1个商品创建成功”

成功页可能出现：

- 继续创建同类券
- 查看提交成功商品
- 同步设置工具列表

如果出现“全站营销额外设置1元”，说明额外优惠没有取消干净。

## 8. 创建后的结束/删除

入口：

`/tool/coupon?tab=1`

每行字段：

- 券类型
- 商品名称/ID
- 面额/使用条件
- 时间
- 发行量/已领取
- 每人限领
- 状态
- 操作：数据、结束、增加发行量

结束流程：

0. 先关掉右上角「新消息」弹窗（`ImportantList_close__d0eKb`）；不关的话点击会落到弹窗上，弹出「请选择反馈内容」，那不是优惠券结束流程
1. 行内点「结束」
2. 弹窗“确认要结束发券吗？”
3. 点「确认结束」
4. 再弹“建议设置活动恢复时间”
5. 点「直接结束」
6. 提示“成功停止该优惠券发行”

注意：

- “结束”文字可能不是 button，需要 DOM click 或点准
- 第一次点结束只弹确认框，不会立即结束
- 第二次必须点「直接结束」，不是「暂时结束并到期恢复」
- 若没走到“成功停止该优惠券发行”，券仍在领取中

## 9. 惊喜券创建入口的坑

在优惠券管理页点「创建惊喜券」后，可能跳到：

`/kit/goods-price-management?from=createResult...`

而不是惊喜券表单。

处理：

- 不要继续在商品价格管理页操作
- 重新打开 `/tool/surprise-coupon`
- 或从优惠券概览的惊喜券卡片点「立即创建」
- 进入后确认页面标题/字段是惊喜券，再继续

## 10. 禁止

- 不确认额外优惠就直接创建
- 用直接改日期输入框代替日期选择器
- 只查选品第1页就判断商品不存在
- 点表头导致整页选中
- 结束券时点「暂时结束并到期恢复」
- 创建成功页出现额外设置还继续批量创建

## 11. 金额必须用户决定

- 券面额、发行张数、每人限领、日期、额外优惠金额全部由用户确认
- 不自动套用页面默认金额
- 页面提示区间限制时，先汇报用户
- 5元、6元、9元这类最低可用值按各券种实际限制选择

## 12. 创建前硬门（必须逐项通过）

1. 券类型已确认
2. 商品已选，数量正确
3. 面额在页面允许范围内
4. 发行张数不超过上限
5. 每人限领已确认
6. 日期通过日期选择器设置
7. 额外优惠 checkbox 全部未勾选
8. 全站营销未勾选
9. 惊喜券额外优惠未勾选
10. 创建按钮只点一次

任何一项不满足：不创建。

## 13. 创建后回读

创建成功后必须回 `/tool/coupon?tab=1` 核验：

- 券类型
- 商品名称/ID
- 面额
- 发行量
- 每人限领
- 有效期
- 状态=领取中
- 无额外优惠/全站营销附加设置

如果成功页出现：

> 您已同步设置以下工具 / 全站营销额外设置 X 元

说明额外优惠没有取消干净：

1. 立即结束这张券
2. 重新创建
3. 重新核验

## 14. 结束券的两段确认

1. 行内点「结束」
2. 弹窗「确认要结束发券吗」→ 确认结束
3. 再弹「建议设置活动恢复时间」→ **直接结束**
4. 校验「成功停止该优惠券发行」
5. 回列表确认状态

禁止点「暂时结束并到期恢复」。

## 15. 代码模式（0.9.15）

`run.mjs` 已封装：

- `coupon-create`
- `coupon-list`
- `coupon-close`

### coupon-create

配置字段：

```json
{
  "mode": "coupon-create",
  "couponType": "商品立减券",
  "goodsIds": ["<商品ID>"],
  "faceAmount": 14,
  "issueCount": 100,
  "couponName": "<内部券名>",
  "extraDiscount": null,
  "surpriseExtraDiscount": null,
  "dryRun": true,
  "confirmCreate": false
}
```

- 不传 `extraDiscount` / `surpriseExtraDiscount` = 两个额外优惠都关闭
- 传 1～100 = 开启并写入该金额
- `dryRun:true` = 只预览，不点创建
- **必须显式 `confirmCreate:true` 才会真正创建**；否则即使 `dryRun:false` 也只预览
- 面额不在平台允许区间时返回 `status:"needs_user_input"`，带 `suggestedRange`，`run.mjs` 退出码 3，不点创建
- 创建后轮询「创建成功」，没确认返回 `failed`，不再假报 done
- 实测某商品：合法面额 **14～25 元**；13、26、30 都是 `券后价 --`
- `perPersonLimit`：惊喜券支持 1/2/3 张并回读校验；商品立减券/店铺关注券页面没有该字段，传了会报 `coupon_per_person_not_supported`
- `useDays`：店铺关注券使用时间 7～90 天可配
- `items`：商品立减券按商品分别设置 `{goodsId, faceAmount, issueCount}`
- `verify:true`：创建后自动回读 active 列表，按券名/面额/商品 ID 校验
- `followScope`：店铺关注券 `all`（全店）/`products`（指定商品）
- `claimDays`：领取时间 1～365 天可配；实测 45 天创建+verify+结束成功
- 低价风险：创建时出现「低价风险预警」返回 `needs_user_input`，不自动确认
- 全店关注券：`verify` 按券名+面额回读；`coupon-close` 可按 couponName 关闭
- 多商品创建已验证：第二商品需无生效商品立减券；否则 checkbox 禁用并提示「该商品已存在生效中的商品立减券」

### 店铺关注券 / 惊喜券

店铺关注券：

- 入口：`/tool/coupon/create?chooseType=3`
- 默认：券名 `指定商品店铺关注券`；领取 365 天；使用 **30 天**（允许 7～90 天）；使用范围 指定商品；没有额外优惠区块
- 面额区间按商品（测试商品 **14～25 元**）
- 列表里的类型可能是 `关注店铺商品券` / `关注店铺券`，代码已做别名，不会漏读

惊喜券：

- 创建入口：**`/tool/surprise-coupon/create`**（`/tool/surprise-coupon` 是列表页）
- 默认：券名 `惊喜券`；领取 90 天；每人限领 **3 张**；没有额外优惠区块
- 面额区间按商品（测试商品 **9～13 元**；8、14 都是 `券后价 --`）
- 结束是单步「确认」；商品立减券/店铺关注券是两步「确认结束 → 直接结束」

### coupon-audit

一次运行、同一 space/page 内完成只读审计：

```json
{
  "mode": "coupon-audit",
  "couponTypes": ["商品立减券", "店铺关注券", "惊喜券"],
  "goodsIds": ["<商品ID>"],
  "probeRange": true,
  "keepOpen": true
}
```

- 先在同一列表页切 `active` / `ended` / `all` 三个页签，读取各自券列表
- 再依次进入三种券的创建页，选同一个商品，读取表单默认值
- `probeRange:true` 时按 `facePlaceholder` 自动测边界：min-1 / min / max / max+1
- 不点击创建；默认 keepOpen，跑完保留页面
- 实测：3 种券 + 12 个面额边界 + 3 个列表页签，一次跑完 **57.3s**

### coupon-list

- 支持 `couponTab`：`active` / `ended` / `all`（也接受中文「生效中 / 已结束 / 全部」）
- `couponAllPages:true` 逐页读取（1～20 页），返回 `pages`、`statusCounts`、结构化 `type/goodsId/face/status/cells`；实测「全部」153 张 / 17 页
- 读取前自动关闭右上角「新消息」弹窗
- 轮询等待表格行稳定，避免刚创建/刚结束时读到旧数据
- 返回 `count`、`coupons`、`tab`、`notices`

### coupon-close

- 必填 `goodsIds`（或 `goodsId`）
- 建议同时给 `couponType` + `faceAmount` 精确匹配；同一商品多张券时不会盲关第一张
- 匹配到多张返回 `coupon_close_ambiguous`
- 读取前自动关闭「新消息」弹窗；否则点击会落到弹窗，弹「请选择反馈内容」
- **必须显式 `confirmClose:true` 才点结束**；否则返回 `preview`（含 rowText）
- 支持 `couponName` 精确匹配；分页已修复（滚动到分页器再点，避免重复读同一页）
- 默认切到「生效中」页签；自动逐页搜索目标券（1～20 页）
- 兼容单步确认（惊喜券：`确认`）和两段确认（商品立减券/店铺关注券：`确认结束` → `直接结束`）
- 最后校验「成功停止该优惠券发行」

### 空间/页面复用

- 只读模式默认 `keepOpen`：结束后 handOff，下次运行复用同一 `pdd-marketing-<店铺>` 空间和页面
- `coupon-list` / `coupon-close` 已在列表页时跳过 `goto`，直接读取；第二次 `coupon-list` 实测从 8.7s 降到 3.6s
- `keepOpen:false` 强制结束并关闭页面

### 创建前协作顺序

1. `coupon-create` + `dryRun:true`：读默认值、合法区间、额外优惠默认值
2. 把 `formDefaults` / `validRange` 汇报给用户，确认面额、张数、券名、额外优惠
3. 再用用户参数跑一次 `dryRun:true`，确认字段回读、券后价、额外优惠状态、按钮可用
4. 用户确认后 `confirmCreate:true` 正式创建
5. `coupon-list` 回读（可用 `couponTab` 查已结束）
6. `coupon-close` 精确结束
