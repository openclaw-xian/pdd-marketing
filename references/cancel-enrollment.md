# 平台活动取消报名：操作方法与踩坑

记录页：

`https://mms.pinduoduo.com/act/register_record`

## 1. 识别要取消的记录

每行包含：

- 活动名称与活动 ID
- 报名商品名称、商品 ID
- 提交时间
- 活动价 / 外场活动价
- 活动状态
- 操作：商品推广、我要调价、**取消活动**、报名详情

取消条件必须同时匹配：

1. 活动名称
2. 提交时间或时间批次
3. 商品范围（如整批误报）

不要只按活动名称取消，否则可能把历史正常报名一起下线。

## 2. 单条取消

1. 找到目标行
2. 点该行「取消活动」
3. 弹出确认框：
   - 标题：取消活动将不可享免费流量
   - 活动名称
   - 商品名称/ID
   - 按钮：保留活动 / **放弃活动**
4. 点「放弃活动」
5. 等待提示「取消成功」
6. 该行状态变为「活动下线」
7. 操作按钮变为「重新报名」「报名详情」

不要点：

- 保留活动
- 我要调价
- 重新报名（除非确实要重新报）

## 3. 批量取消

记录页有「批量取消报名」，但表头自定义 checkbox 很容易点不中。

实测风险：

- 表头 label 点了但没有勾选任何行
- 再点批量取消提示「请先勾选报名记录」
- 批量取消若选错范围，可能影响其他活动

推荐：

- 优先逐行「取消活动 → 放弃活动」
- 只有能精确勾选目标行时才用批量取消
- 勾选后必须再次核对选中商品和活动范围

## 4. 分页取消（重点）

记录页每页默认 10 条，底部有页码和下一页。

页码组件：

- `LI[class*=PGT_pagerItem]`
- 当前页带 `PGT_pagerItemActive`
- 下一页箭头/页码

正确流程：

1. 先回到第 1 页
2. 逐行取消当前页所有目标记录
3. 当前页没有可取消链接后，**点下一页**
4. 每一页重复：
   - 找匹配记录
   - 取消
   - 放弃活动
   - 检查该页剩余可取消数
5. 直到所有目标页都核验完

每页核验字段：

- 匹配记录总数
- 仍有「取消活动」按钮的数量
- 状态是否均为活动下线

实测：

- 第1页：10 条，活跃 0
- 第2页：10 条，活跃 0
- 第3页：8 条，活跃 0
- 第4、5页：无匹配记录

取消后部分记录会从列表消失，分页总数会变化；不能只看总条数判断是否完成。

## 5. 不能只检查一页

踩坑：

- 只看第1页就汇报“全部取消”
- 实际上第2页还有大量报名成功记录
- 记录页刷新后页码会变化，需要重新定位
- 某页没有「取消活动」不代表其他页也没有

必须：

- 逐页核验
- 用「是否还有取消活动按钮」判断活跃记录
- 每页汇报总数/活跃数
- 最后汇总剩余活跃数必须为 0

## 6. 取消后的回读

检查：

- 状态是否为「活动下线」
- 是否出现「重新报名」
- 是否没有「取消活动」
- 是否没有「报名成功」「报名进行中」

取消成功后不要再次点「重新报名」，否则会再次报名。

## 7. 安全规则

- 取消是写操作，必须用户明确授权
- 先确认活动名称 + 提交时间批次
- 取消前记录完整商品清单
- 只取消指定批次，不碰历史正常报名
- 不把「批量取消」当默认方案
- 每页核验，禁止只看第一页
- 取消后给用户完整的取消/剩余清单
